- No `content-encoding` header: CloudFront did not compress, as expected with `CachingDisabled`.
- The status line and headers arrive **together with the first event**. The Lambda runtime writes the HTTP prelude on the first write, so nothing reaches the client until the model's first token.
- Lambda platform report for this request: `initDurationMs` 474, `durationMs` 2659, `maxMemoryUsedMB` 162 (of 1024). The handler's own log: first delta 970 ms after it started, total 2642 ms.

## The skeleton page in Chrome

Headless Chrome (a throwaway profile) opened `https://<distribution>/`, signed in as the test user through the page's SRP form, and sent *"In about 60 words, what should I bring to my first appointment?"*. The script sampled the length of the rendered reply every ~100 ms:

```
status line: HTTP 200 · headers 1166 ms · first text 1170 ms · done 2789 ms · 40 text_delta events in 37 network chunks · 79 output tokens
reply length (ms since send → chars): 1251→5, 1458→19, 1561→131, 1666→150, 1769→201, 1873→210, 1977→222,
                                      2082→229, 2186→250, 2497→298, 2602→321, 2706→349
```

The browser receives and renders the text progressively too, over HTTP/2 from CloudFront. An earlier run caught a page bug: `form { display: grid }` beat the UA's `[hidden]` rule, so the login form never hid. Fixed in the page's CSS.
