## Things the numbers need beside them

- **Finals before Send.** In 3 to 7 of each browser's 20 main runs, Transcribe had already sent the last final result before Send was pressed, because the speaker paused before pressing it. Those runs count as 0 ms of stop→final (r1/A-1's metric), and the summary counts them in a "final before Send" column. In every run with a final after Send, the final arrived within 285 ms (304 ms in the variant runs). The summary also reports Send→stream end, which is what the patient waits for in a real Transcriber (`stop()` resolves when the response stream ends). Its p95 was at most 382 ms on every browser.
- **One late Send.** One iOS Safari ~5 s main run has 17.0 s of audio: Send was pressed about 7.5 s after the final. It counts as a successful 0 ms sample. Without it, iOS Safari's p95 is unchanged (218 ms).
- **WER is informational.** It is word error rate against the full script. The ~60 s runs score 0.15 to 0.20 mostly because the 60 s auto-send cuts the script before its last sentences. The ~5 s runs score 0.00 on every browser.

## Export repair (redaction bug)

The page redacted exports with `\b\d{12}\b`, meant for AWS account IDs, and the Mac's dev-server endpoint applied it again. That pattern also matched the 12 fractional digits that Chrome, Android Chrome and macOS Safari give `performance.now()` values (`"stop": 6744.399999999674`). It left numbers like `"stop": 6744.<account>`, and the files no longer parsed (`summarize.ts`: "Unterminated fractional number in JSON").

- **Repair:** in each export, `(\d)\.<account>` was replaced with `$1`, which drops the damaged fraction and keeps the integer milliseconds. The fraction only ever held sub-millisecond digits, so this is a faithful repair: every reported statistic is in whole milliseconds. The counts were 31 values in the Android Chrome export, 105 in Chrome (desktop) and 7 in macOS Safari. The iOS Safari and Firefox exports had none, because their clocks give coarser values.
- **Checks:** after the repair, the only remaining `<account>` in each file is the intended one, inside the denied call's role ARN. Every file parses. The files contain no 12-digit run, no `us-east-1:` or `us-east-1_` ID, no LAN address, no `eyJ` token, no access key and no `@`.
- **The fix in the code:** `src/redact.ts` now matches `(?<![\d.])\d{12}(?!\d)`, so a run of 12 digits that follows a decimal point is left alone. `redact.check.ts` checks this (`npm run check -w spikes/s3-transcribe-browser`), and `summarize.ts` now names any export that doesn't parse.
